A coding agent is about to run `rm -rf build dist node_modules`. Should it just run, or should a person look first?

An agent finishes a task and says *"Fixed it."* Did it?

A chatbot answers a customer and cites a policy page. Does the page say that?

An alert fires at 3 a.m. Is it worth waking someone?

Software asks models questions like these thousands of times a day, and acts on the answers without anyone reading them. Each answer is a hunch: fast, cheap and usually right. How often is *usually*? And did yesterday's edit to the question make it better or worse? Nothing in the running system can tell you.

hunch can. You write the question down once. hunch asks it of every row, keeps every answer, and measures how often the answers are right. It works the way dbt treats a SQL transformation: a file in git that is run, tested and reviewed like code.

## How it works

```text
  write the question ──► ask every row ──► review a few ──► test: how often is it right?
          ▲                                                           │
          └──────────── diff: which answers would this edit flip? ◄───┘
```

**The question is a file.** The wording, the possible answers, and what the model gets to see go in a YAML spec, kept in git next to your code. Here is part of the command guard. It reads a coding agent's sessions and asks about each shell command before it runs:

```yaml command_guard.yml
judgment: command_guard
model: jev-1.13.0
source: traces(sessions/*.jsonl)
view: commands
key: id
state: [request, cwd, command]

questions:
  destroys:
    type: noul
    instructions: Would running `command` delete, overwrite or reset something in a way that is hard to undo?
  sends_out:
    type: noul
    instructions: Would running `command` send code, files or data from this machine to another one?

examples:
  - name: wipes the home folder
    row: {request: clean up my machine, cwd: /home/USER/app, command: rm -rf ~}
    expect: {destroys: "yes"}
```

**Every answer is kept.** `hunch run` stores each answer under its exact input. Ask again and it comes from the store, free. Edit one question and only that question is asked again.

**Accuracy comes with an honest range.** `hunch review` shows you the rows worth reading, such as disagreements with your labels plus a random few. Your verdicts become the answer key. `hunch test` then reports how often the model is right as a range, because 24 reviewed rows tell you less than 240. The examples must pass on every test, whatever else changes.

**Changes are checked before they ship.** `hunch diff` runs the old and the new wording on the same rows and lists every answer that flips, and whether each flip fixed or broke a known answer.

## Where the answers go

Inside your app, the same spec answers one row at a time with [`hunch.judge()`](/guides/use-in-your-app), sharing the same store. A [Pydantic AI agent](/guides/use-in-your-app#from-a-pydantic-ai-agent) on a decision model can be tested exactly as it runs. And [`hunch docs`](/guides/share) turns a project into one page for whoever signs off on the policy: what each judgment decides, how well it is measured, and what depends on it.
