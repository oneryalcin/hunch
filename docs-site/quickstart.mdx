---
title: "Quickstart"
description: "Run, test, change and review a judgment over 40 sample support tickets. About five minutes and a tenth of a cent."
---

This page takes one judgment through its whole life: asked, measured, changed, reviewed. The data is 40 made-up support tickets, each asked three questions. Which team should handle it? Is it urgent? How frustrated is the customer?

You need [uv](https://docs.astral.sh/uv/) and a TypeSafe API key. Everything below costs about $0.0015.

<Note>
The repository is private until v0.2. If `uv tool install` fails with a 404, ask for access.
</Note>

<Steps>
  <Step title="Install">
    ```sh
    uv tool install git+https://github.com/oneryalcin/hunch
    export TYPESAFE_API_KEY=...
    ```
  </Step>

  <Step title="Copy the example">
    ```sh
    hunch init tickets my-tickets
    cd my-tickets
    ```

    Open `ticket_triage.yml`; it is 30 lines. Its first line points your editor at hunch's schema: VS Code and Cursor (with the YAML extension) complete keys and flag mistakes as you type. Only `department` has an answer key, the `gold_department` column.
  </Step>

  <Step title="See the cost before paying it">
    ```sh
    hunch compile .
    ```

    ```
    # ticket_triage: 40 rows in; 120 answers planned, 0 cached, 120 to ask, ~18,620 input tokens, ~$0.00078 (jev-1.13.0)
    ```

    `compile` sends nothing. Above that last line it prints the exact request for the first ticket, which is everything the model will see.
  </Step>

  <Step title="Run it">
    ```sh
    hunch run . --max-cost 0.01
    ```

    ```
    ticket_triage: 40 rows in; answers: 0 cached, 120 asked in 40 requests, 19,101 input tokens, $0.00080
      department: 0 rows below act=0.8 → review queue
    materialized 1 table(s) in .hunch/store.sqlite
    ```

    `act=0.8` comes from the spec: an answer less confident than that goes to a person for review. Here no ticket fell below it.

    Run the same command again. This time it reports `120 cached, 0 asked` and `$0.00000`. Each answer was stored under its exact input, and that input has not changed.
  </Step>

  <Step title="Measure it">
    ```sh
    hunch test .
    ```

    ```
    department (choice, 40 rows)
      gold: 40 rows (40 from source, 0 from review)
      PASS accuracy 100.0% (min 90%)
      PASS calibration error 0.003 (max 1)
             dial   automated   wrong among automated
             …
             0.80      100.0%                    0.0%  ← act
    ```

    `department` passes the `min_accuracy: 0.90` written in the spec. The dial answers a practical question: if you acted only on answers above a given confidence, how many tickets would that cover, and how many of those would be wrong?

    `urgent` and `frustration` print nothing: without gold there is nothing to measure against. The last step makes some.
  </Step>

  <Step title="Change a question, and see what it changes">
    Put the folder in git, so there is a version to compare against:

    ```sh
    git init -q && echo .hunch/ > .gitignore && git add . && git commit -qm tickets
    ```

    Now make `urgent` stricter in `ticket_triage.yml`:

    ```yaml ticket_triage.yml
      urgent:
        type: noul            # a yes/no question
        instructions: Does the customer say their business is blocked right now (an outage, a deadline today, money lost)?
    ```

    ```sh
    hunch run . --max-cost 0.01
    hunch diff . --against git:HEAD --max-cost 0
    ```

    The run asks 40 questions, not 120: only `urgent` changed. The diff then compares the two versions from the store, so it costs nothing:

    ```
    department: unchanged (same keys, 0 calls)

    urgent: 2/40 rows flip (1 within noise band)
      probabilities moved: mean |Δ| 0.105, mean Δ p(yes) -0.100
        #  40   yes 0.92 → no 0.95          Cancel and refund | The product doesn't…
        #  11    no 0.51 → yes 0.54  ~noise SSO broken | Okta login loops back to t…
    ```

    Two tickets flipped, and ticket 11 was a near tie both times, so it is marked as noise. The mean shift shows what flips alone hide: the new wording lowered p(urgent) across the board, by 0.10 on average.
  </Step>

  <Step title="Review">
    ```sh
    hunch review . --limit 5
    ```

    Review shows one ticket at a time and asks for the right answer. Here the model agrees with every key, so you get random spot checks, where Enter agrees with the marked answer. Verdicts go to `ticket_triage.reviews.csv`, and the next `hunch test` counts them as gold.
  </Step>
</Steps>
