---
title: "Quickstart"
description: "Review eight real Enron emails: ask one question, check it against published judgments, and see what a wording change does."
---

Imagine you have thousands of emails and need to find those worth reading for an inquiry into a company's lobbying. You cannot read them all first. You also cannot assume that an email about a law describes an effort to change it.

This lesson uses eight lightly redacted messages from the public Enron email collection. Four were marked relevant and four irrelevant by reviewers in the [TREC 2010 Legal Track](https://trec.nist.gov/data/legal10.html). You will ask one question, check its answers, then revise the question. The eight cases were chosen to teach the workflow; they do **not** estimate how well it works on the full collection. [Source and editing notes](https://github.com/oneryalcin/hunch/blob/main/src/hunch/recipes/enron_review/NOTICE.md).

You need [uv](https://docs.astral.sh/uv/) and a TypeSafe API key. The commands below cap model spending at one cent each.

<Steps>
  <Step title="Get the eight emails">
    ```sh
    uv tool install hunch-ai
    export TYPESAFE_API_KEY=...
    mkdir my-review && cd my-review
    curl -fsSLO https://raw.githubusercontent.com/oneryalcin/hunch/main/src/hunch/recipes/enron_review/emails.csv
    curl -fsSLO https://raw.githubusercontent.com/oneryalcin/hunch/main/src/hunch/recipes/enron_review/lobbying.yml
    curl -fsSLO https://raw.githubusercontent.com/oneryalcin/hunch/main/src/hunch/recipes/enron_review/NOTICE.md
    ```

    The three small files come from this repository, so the lesson works with the current `hunch-ai` release. `emails.csv` holds the messages, `lobbying.yml` holds the question, and `NOTICE.md` explains the sources. The model reads only the subject and redacted body of each email; the reviewers' `gold` answers are kept for the test.
  </Step>

  <Step title="Ask one question">
    ```sh
    hunch run lobbying.yml --max-cost 0.01
    ```

    The spec asks: **Does this email describe an attempt to influence a law, regulation, or public policy?** `run` asks Jev that question of each email and writes a table of answers to `.hunch/store.sqlite`. Jev supplies the yes/no probabilities; hunch keeps the question and the answers together.

    Run the command again. With the same model, question, and email text, the answers come from the cache and cost nothing. A new question or new email needs a new model answer.
  </Step>

  <Step title="Check against the reviewers">
    ```sh
    hunch test lobbying.yml --max-cost 0
    ```

    `test` compares the model's answers with the eight published judgments. Look at the disagreements, not only the accuracy number. For example, an email that merely reports a bill's passage is different from one proposing comments to a regulator. The test uses cached answers, so `--max-cost 0` refuses any missing model calls.

    This is a deliberately balanced set of four yes and four no cases. Its score is useful for learning what the question means, **not** for claiming a real-world error rate. The [document-review cookbook](/cookbooks/document-review) shows how to estimate one for a different legal request using a larger, sampled collection.
  </Step>

  <Step title="Change the question, then inspect the change">
    Save the first version beside the spec:

    ```sh
    cp lobbying.yml first.yml
    ```

    In `lobbying.yml`, replace the `instructions:` line with this more specific reading:

    ```yaml lobbying.yml
    instructions: >-
      Is this email about Enron's efforts to influence a law, rule, or public
      policy? Include proposed comments to regulators, legislation the company
      seeks to change, and preparing testimony for a public hearing. Exclude
      messages that only report a law, discuss routine regulatory work, or
      arrange travel without proposing a policy position.
    ```

    ```sh
    hunch diff lobbying.yml --against first.yml --max-cost 0.01
    ```

    `diff` asks the revised question, lists the emails whose answers changed, and compares both versions with the same reviewer judgments. The changed question needs new answers; the old ones remain cached. Read the flips before deciding whether the rewrite helped. Eight chosen cases cannot settle that question for a larger archive.
  </Step>
</Steps>
